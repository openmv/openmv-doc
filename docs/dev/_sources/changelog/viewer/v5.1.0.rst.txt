v5.1.0
======

v5.1.0 brings OpenMV Viewer up to date with :doc:`OpenMV IDE 5.1.0
<../ide/v5.1.0>`, with which it shares its code. The pane under the frame
buffer becomes a set of **live views** -- the histogram plus Board Info,
Memory, Statistics, and the new **Channels** view that shows the values and
controls a product's script publishes -- multi-sensor cameras get a **frame
buffer source selector**, new boards are supported, and the firmware and
ROM-file-system recovery paths the Viewer keeps were hardened by a full
review. It is built on Qt Creator 14.0.2 and bundles firmware v5.0.1.

Highlights
----------

- **Pane views** -- a selector in the histogram pane's title bar switches it
  between the **Histogram**, **Board Info** (the connected camera's hardware,
  versions, and capabilities), **Memory** (live graphs of the camera's heap
  and memory pools), **Statistics** (debug-protocol and per-channel event
  counters), and **Channels** views.
- **Channels view** -- when a product's script publishes channels, the Viewer
  shows them live: readouts and controls (labels, toggles, sliders, spin
  boxes, radio buttons, line edits, selectors, buttons, and text), waveform
  graphs with a spectrum analyzer, and depth maps with palettes, scaling, and
  tone mapping. Graphs and maps can be recorded to CSV, WAV, NumPy, or Edge
  Impulse files, and the last values stay on screen when the script stops.
- **Frame buffer source selector** -- cameras with more than one image sensor
  show a selector to choose which sensor streams to the Viewer, or to turn
  streaming off; the JPG toggle became a JPG / RAW streaming-mode selector,
  and the pane's title names the format each frame arrived in.
- **New hardware** -- the OpenMV N6 Classic board and the FLIR Lepton 3.1R and
  UW sensors.

Bug fixes
---------

Two review passes over every change since v5.0.0 fixed, among others, the
following that apply to the Viewer
(`ccea3b17d01 <https://github.com/openmv/qt-creator/commit/ccea3b17d01>`__,
`71826200611 <https://github.com/openmv/qt-creator/commit/71826200611>`__):

- The macOS warnings could swallow the "Yes" of the firmware-upgrade prompt.
- A camera's drive association could lose the race to other volumes, and the
  single-drive fallback was unreachable when the camera had been plugged in
  for more than ten seconds
  (`9877480c304 <https://github.com/openmv/qt-creator/commit/9877480c304>`__).
- The GENX320 event sensor disabled the frame buffer; a saved sensor
  selection did not survive a restart.
- Loading a ROM file system onto the camera: Cancel during the write ended
  silently with a possibly partial ROMFS, and a dfu-util error was reported
  as success. The bootloader is now asked to leave DFU after a cancelled
  operation so the camera comes back on its own.
- A bricked N6 Classic was repaired with the plain N6 bootloader and
  firmware; a custom firmware zip onto a board already in bootloader mode
  flashed the release build instead.
- The read flush that runs before protocol detection is bounded (issue #336)
  (`77cd13af76f <https://github.com/openmv/qt-creator/commit/77cd13af76f>`__).

Platform and tool support
-------------------------

- **Qt Creator base:** 14.0.2 (shared with OpenMV IDE).
- **Bundled firmware:** v5.0.1.
- **New boards and sensors:** OpenMV N6 Classic; FLIR Lepton 3.1R and UW.

Breaking changes
----------------

None. The JPG toggle in the frame buffer's title bar is now a JPG Mode / RAW
Mode selector.
